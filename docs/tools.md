# Tools

The `mcp-plan` server exposes the following tools over MCP. All results are
returned as structured JSON content. Task ids are UUIDs generated by the server.

## `task(id)` — fetch a single task

Returns the full task object for `id`.

```text
task({ id: string })
```

```json
{
  "id": "…",
  "parent_id": null,
  "source_id": null,
  "title": "Research the API",
  "description": "Read .md docs, list endpoints",
  "status": "ready",
  "priority": "medium",
  "retries": 0,
  "created_at": "…",
  "updated_at": "…",
  "estimated_tokens_in": 4000,
  "estimated_tokens_reasoning": null,
  "estimated_tokens_out": 800
}
```

Fields: `id`, `parent_id`, `source_id`, `title`, `description`, `status`,
`priority`, `retries`, `created_at`, `updated_at`, `estimated_tokens_in`,
`estimated_tokens_reasoning`, `estimated_tokens_out`.

- `status`: `ready` | `success` | `failure` | `escalated`
- `priority`: `critical` | `high` | `medium` | `low`

## `children(parent_id?)` — list children of a task

Returns a compact array of direct children. When `parent_id` is omitted (or
`null`), returns root-level tasks.

```text
children({ parent_id?: string })
```

```json
[
  {
    "id": "…",
    "title": "Outline the design doc",
    "status": "ready",
    "priority": "high",
    "estimated_tokens_in": 1200,
    "estimated_tokens_reasoning": null,
    "estimated_tokens_out": 400
  }
]
```

## `insert(object, parent_id?)` — create a task

Inserts a new task with `status='ready'` and returns its `id`.

```text
insert({ object: task, parent_id?: string })
```

`object` fields: `title` (required), `description`, `priority`, `source_id`,
`estimated_tokens_in`, `estimated_tokens_reasoning`, `estimated_tokens_out`.

```json
{ "id": "…" }
```

## `complete(task_id, status)` — mark success or failure

Sets `status` to `success` or `failure`. Returns the updated task. Any other
value is rejected.

```text
complete({ task_id: string, status: string })
```

## `fail(task_id, status)` — record a failure

Increments `retries` and sets `status` to `failure`; `status` here is the
failure reason and is recorded in the logs. The task is escalated instead once
`retries` reaches the configured `max_retries`. Returns the updated task.

```text
fail({ task_id: string, status: string })
```

## `escalate(task_id)` — block for human review

Marks the task as `escalated`. Escalated tasks are excluded from `queue()` until
a human clears them (via `ready`).

```text
escalate({ task_id: string })
```

## `ready(object, task_id)` — update and requeue

Updates mutable fields (`title`, `description`, `priority`,
`estimated_tokens_*`) and sets `status` back to `ready`. Returns the updated
task.

```text
ready({ task_id: string, object: task })
```

`object` accepts any subset of the mutable fields.

## `queue()` — tasks needing work

Returns tasks requiring attention, sorted by `priority`
(`critical > high > medium > low`) and then by workload type (`planning` before
`execution`), bounded by the configured `queue_limit`.

Excludes `success` and `escalated` tasks. Failed tasks whose `retries` reach
`max_retries` are automatically escalated and omitted.

```text
queue({})
```

```json
[
  {
    "task": {
      "id": "…",
      "title": "…",
      "status": "ready",
      "priority": "critical",
      "…": "…"
    },
    "kind": "planning",
    "duration_secs": 852
  }
]
```

The `kind` (`planning` | `execution`) is decided by the server:

```text
duration_secs = estimated_tokens_in / tps_in
  + (estimated_tokens_reasoning + estimated_tokens_out) / tps_out
```

When `duration_secs > max_task_duration_secs` the task is `planning`, otherwise
`execution`. The agent only ever estimates tokens; classification is enforced by
the server.
